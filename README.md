## 简介

面向国内 Android 用户的多 AI 圆桌工具。应用本身无需注册账号、没有自建后端；用户只需在内嵌的 AI 官网完成一次登录，之后由 App 复用本机 WebView 登录状态，汇总多家回答并支持后续讨论。

> 本项目通过真实 AI 网页工作，不是厂商官方 API。网页 DOM 改版后可能需要更新适配器。

## 产品定位

- 默认成员：DeepSeek、豆包、Kimi。
- 可选成员：千问、元宝、智谱。
- 每次可选择 2-4 家 AI。
- 聚焦普通用户，尤其是中老年用户的日常提问、群策群力和幻觉风险提示。
- 登录信息、成员选择和讨论历史只保存在 Android 应用沙箱内。

## 界面风格

「设置 → 界面风格」提供六套可切换的风格，选中即时生效并保存在本机。
每套风格同时决定配色、圆角、描边粗细、阴影模型和字号基准，不只是换主色：

| 风格 | 定位 | 特点 |
|---|---|---|
| 净白 | 默认 | 白底、渐变标题；容器只靠浅灰填色区分，不画描边（对标豆包 / Kimi） |
| 清朗 | 经典 | 明亮通透的青蓝，圆角适中，浅描边 |
| 墨韵 | 中式 | 宣纸底 + 朱砂主色，小圆角、无阴影、标题衬线 |
| 夜航 | 深色 | OLED 友好的深蓝灰，系统状态栏图标跟随反色 |
| 长辈 | 无障碍 | 纯白高对比、字号 ×1.18、触摸目标 60dp、2dp 粗描边 |
| 暖阳 | 亲和 | 暖橙渐变，大圆角与柔和阴影 |

「长辈」风格可与「大字模式」叠加，二者互不冲突。

## 结果页：点击状态行展开回答

- 每家 AI 一条状态行，显示名字、模式、回答预览与当前状态；支持实际选中的 2-4 家成员。
- 点状态行原地展开完整回答；再次点状态行、回答正文或「收起」折叠，可同时展开多家。
- 复制、分享、跳转原网页和失败补救仍在对应回答内，操作按钮不会触发正文折叠。
- 状态列表下方是「继续追问」与最多两行的输入框，再下方并排放「队长总结 / 观点讨论 / 独立迭代」。
- 「队长总结」按钮展开队长、深度与总结结果。观点讨论可不填要求；独立迭代需要本轮原文或附件；仅附件时使用界面说明的默认问题。
- 右上角「新会话」回到空白提问页，旧讨论保留在历史中；仍在回答时先确认停止等待。底部保留圆桌 / 历史 / 设置主导航，不再放新问题按钮或 AI 分段切换。

## 独立并行发送（0.13.1）

- 并行模式下，每家网页就绪后独立开始发送；不再等待前一家上传、解析附件或确认送达。较慢成员不会拖住其他成员。
- 各家拥有独立的发送任务、超时和取消状态；页面点击、输入时短暂协调焦点，等待上传和回答时可同时推进。
- 新对话按成员分别准备；某家页面加载失败或超时会明确标记失败，避免把新问题误发到旧对话。整体停止、新会话仍撤销全部在途发送。
- 串行模式仍等待上一家回答结束；失败恢复仍按用户确认逐家处理，不自动重发。首轮重发先确认新对话，后续讨论 / 迭代重发继续原对话；重新提取不导航、不重发。
- 通过隔离模拟器的会话与网页夹具验证；本版本三家官网的单张 PNG、单个 TXT 并行上传及回答核验范围见下文，网页版本和账号限制仍可能影响结果。

## 附件与失败恢复（0.13.0）

- 首页及继续追问支持添加照片 / 文件，显示名称并可移除；一次最多 3 个，单个 10 MB、合计 20 MB。支持 PNG、JPEG、PDF、TXT、DOCX。
- 附件和问题一起交给参与的 AI；观点讨论 / 独立迭代发给本轮成员，队长总结只发给选定队长。只有附件时默认提问为「请阅读附件，概括主要内容并给出你的分析和建议。」
- 每家网页必须确认附件上传就绪后才发送文字。文件类型不支持、上传失败、超时或取消均明确停止，不会悄悄变成纯文字提问；厂商网页及账号限制可能导致单家失败。
- 当前圆桌附件适配 DeepSeek、豆包、Kimi；选择其他成员时明确提示尚不支持附件。文件是否可用还取决于对应官网的账号、格式和解析服务。
- 0.13.2 适配豆包当前上传菜单及附件区域，识别 DeepSeek 图片卡和手机 WebP 转换，并支持 Kimi 当前发送控件。转换后的图片必须与本次选图唯一对应且身份稳定；歧义、额外附件或身份变化会明确停止。上传点击等待网页处理后归还焦点；页面更新较慢时同一请求不会重复点击发送。
- 附件复制到应用私有目录，历史和重试使用同一份副本，不依赖原文件选择权限。导入时自动回收不再被草稿、讨论历史或上传引用的副本；引用无法确定时保守保留。附件总存储上限 200 MB。
- 结果页出现失败项时，顶部直接显示恢复卡：先「重新提取」已有回答（不发送）；需要重发时确认后按原轮内容和附件逐家重发失败项，已成功的成员保持原样。也可打开网页处理登录 / 验证，或保留历史开新会话。
- 不会在重启后自动重发。停止等待、新会话和恢复其他历史会撤销尚未完成的发送；文件选择器的迟到结果不能混入新会话。
- 移除 App 语音输入入口及识别逻辑；系统输入法自身的听写功能不受影响，大字模式保留。

2026-09-10，独立验收在保留登录的隔离 Android 环境中，使用 0.13.2 的 r9 debug 候选，通过 App「新会话 → 系统选文件 → 开始讨论」完成单张 PNG 和单个 TXT 的两轮初始自动发送；DeepSeek、豆包、Kimi 的 App 展开正文均读对文件中的随机编号及数量，没有网页手工操作或失败项重发。其他格式、多附件、其他账号和网页版本不在本次真实验收范围；正式 R8 包实传及签名覆盖升级另按发布流程验收。

## 队长总结（0.11.0）

0.8 ～ 0.10 的"队长"是观点讨论轮里拿一套不同 prompt 的固定角色，家人反馈那条整合"比较浅"——
根因是它塞在讨论轮里、限 400 字、只引用别家回答的片段。0.11 起：

| 环节 | 现在的做法 |
|---|---|
| 初始回答 / 观点讨论 | 人人平等，没有队长徽章和置顶 |
| 队长总结 | 独立一步，点击「队长总结」展开：**选队长**（成员中任一家，默认上次选的 / 第一位）+ **选深度** |
| 喂给队长的材料 | 几家的**完整回答**（上限 14,000 字），只在超出该站上下文预算时逐步压缩 |
| 深度 | 简明（≤200 字：一句话结论 + 各家一句点评 + 最该做的一件事）/ **标准**（默认，≤500 字：结论、共识、分歧、建议）/ 深入（≤1200 字：先逐条核对数字与事实，再给结论、依据与风险、分步做法） |
| 深入 + 队长没开深度思考 | 明确读到队长的深度思考关着时提醒"先去它的网页打开"；读不到不提醒 |

队长与深度的选择会记住，下次默认还是它。

## 模型 / 思考模式小字（0.11.0）

每家 AI 网页里都有深度思考、联网之类的开关，家人不知道 AI 是在哪种模式下回答。App 用一段**只读**脚本
（不点任何开关）读网页上的当前状态，写在总览卡和回答卡的小字里；读不到写"模式 未知"，绝不猜：

| 站点 | 能读到什么 | 来源 |
|---|---|---|
| DeepSeek | 模型（Instant / Expert / Vision）· 深度思考 开/关 · 联网 开/关 | 根页 radio / 对话页顶栏；`.ds-toggle-button` 的 aria-pressed，localStorage 兜底 |
| Kimi | 模式（Instant / Thinking …）· 力度（High …）· 深度思考 开/关 | 输入区 `.current-model .name` / `.current-effort` |
| 千问 | 模型（Qwen3.7-千问）· 快速 / 思考 · 深度思考 开/关 | 顶栏模型名；输入区胶囊 aria-label |
| 元宝 | 模式（Expert …） | `aria-label="Switch model"` 按钮文字 |
| 豆包 | 输入模式（对话 / 工作任务） | 手机版网页没有深度思考开关，只有这个 |
| 智谱 | 模型（GLM-5.2）· 联网 开/关 | h5 页面没有控件，从 Vuex 的 `Home.configuration.home.commonModel` / `Conversation.is_networking` 读 |

另外每条回答里出现过思考过程块时，卡片上会打「已深度思考」标签——这是站点自己承认的，比开关状态更可信。

## 面向家人的引导与兜底（0.7.0）

- 首次启动三步说明；登录引导页按「第 1、2、3 家」编号，附「怎么登录？」三句话。
- 打开某家 AI 的网页时顶部有登录提示条，探测到登录成功后变成绿色「已登录 · 返回圆桌」。
- 底栏只有三个去处：圆桌 / 历史 / 设置。首页只有一个永远可点的主按钮，没登录够两家时它带你去登录。
- 每家 AI 失败时显示白话「怎么办？」（原因 + 下一步），按钮按建议排序；队长总结失败同理。
- 断网提示、上次异常退出提示都是非弹窗的提示条。
- 设置页「遇到问题？按顺序试」：重新加载 AI 网页 → 清除卡住的讨论 → 重启应用（独立进程中转，登录不丢）。

## 主要功能

- 并行回答：多家独立发送、上传附件和等待回答；卡片分别显示准备网页、正在发送及回答进度。
- 每个新问题都在各家网页里开一条新对话，不带上一题的上下文；历史会话记录了各家当时的对话地址，
  打开历史会一并把各家网页切回那条对话，接着「观点讨论」不会发错地方。
- 严格串行：上一家稳定完成或失败后，才发送给下一家。
- 独立迭代：必须输入本轮 Prompt；向上一轮成功成员发送完全相同的用户原文，不附加原问题、旧回答或 App 模板。
- 观点讨论：每家收到其他成员的最新观点，可附加用户本轮讨论要求。
- 队长总结：选一位 AI 当队长、选深度（简明 / 标准 / 深入），它拿到几家的完整回答后整合成一条。
- 结果页状态行原地展开回答；每家显示模型 / 思考模式小字与「已深度思考」标签。
- 单家补救：重发、重新提取或跳过，不要求整轮重跑。
- 本地历史：最近 20 个会话，支持冷启动恢复和损坏索引自愈。
- 照片 / 文件附件、大字模式、六套界面风格。
- 每家回答可展开全文、单独复制或分享，一键跳转到该家网页。
- 提问阶段就提示上下文预算风险，而不是等到点「观点讨论」才失败。
- 一键复制或调用 Android 系统分享总结；每个问题记录提问时间，结果页与历史列表都显示。
- 24,000 字问题上限、12,000 字回答截取提示、最近 8 轮有界历史和上下文预算保护。
- 用户提问中不包含内部 request ID 或 `AI_ARENA_ID`。

## 版本与升级规则

- `versionName` 使用语义化版本：`主版本.次版本.修订版本`。
- `versionCode` 每次发布必须严格递增，供 Android 判断升级顺序。
- 当前基线：`versionName=0.13.2`，`versionCode=22`。
- 下一次小修复示例：`0.13.3 / versionCode 23`。
- 下一次向后兼容新功能示例：`0.14.0 / versionCode 23`（与上例二选一，实际发布时继续递增）。
- 破坏兼容性的改动：升级主版本。

为了保留网页登录态，升级必须保持：

- 相同 `applicationId`：`com.tianlin.aiarena`。
- 相同签名密钥。
- 覆盖安装；禁止卸载、`pm clear`、擦除 AVD 或更换包名。

分发给用户请用 **release 包**（已签名、开启 R8，约 1.4 MB）：

```text
app/build/outputs/apk/release/app-release.apk
```

release 签名从仓库外、且 gitignore 的 `keystore.properties` 读取；该文件不存在时
（例如 CI）构建照常进行，只是产出未签名包。

> **密钥丢失 = 永远无法对已安装版本做保登录升级。** 请把 keystore 与其
> properties 文件异地备份（网盘 / 密码管理器 / 离线介质），且不要提交进 git。

## 隐私与安全边界

- App 不读取、导出或上传 Cookie、Token。
- 无 AI 圆桌账号、无自建服务器、无跨设备同步。
- 网页登录数据由 Android WebView 保存在本机应用沙箱。
- “重新提取”不会重发问题；如果 WebView 已切到另一条对话，需要先打开对应原对话。
- AI 输出可能不准确，尤其是健康、金融和政策信息，仍应查阅权威来源。
